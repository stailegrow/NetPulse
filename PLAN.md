# PingPlotter ALT — план разработки

Рабочее название: **NetPulse** (можно поменять).
Кроссплатформенный монитор доступности и качества сети: macOS → Windows (→ Linux бесплатно «в подарок»).
Не клон PingPlotter, а свой инструмент, заточенный под мониторинг множества сервисов компании.

---

## 1. Что берём у PingPlotter и что делаем лучше

| PingPlotter | У нас |
|---|---|
| Target Bar + одна цель на вкладку | **Дашборд всех целей сразу** (плитки/таблица со статусом, спарклайнами), клик → детальный экран |
| Trace Graph (таблица хопов: Hop, Count, IP, Name, Avg, Min, Cur, PL%, Latency-бар) | То же + ASN/провайдер, геолокация хопа, подсветка «виноватого» хопа |
| Timeline Graph (latency + packet loss во времени) | То же, быстрый canvas, зум/пан мышью, синхронизация нескольких графиков |
| Focus (усреднение по N последних сэмплов или диапазону) | Выделение диапазона прямо на графике → таблица пересчитывается |
| Summary Graphs | Сводный экран: аптайм %, SLA, худшие цели, heatmap по часам |
| Workspaces | **Группы** (Офис, Датацентр, SaaS, VPN…) + теги, импорт списка целей |
| Alerts (email, звук, лог, команда) | Алерты + уведомления macOS/Windows, Telegram, Slack/webhook |
| Route Changes | Детектор смены маршрута с историей и diff |
| Auto-Save / Export CSV | SQLite-история всегда, экспорт CSV/JSON/PNG-отчёт |
| Только ICMP/UDP/TCP трассировка | + **HTTP(S) проверки** (код, время, TLS-срок сертификата), DNS-проверки, TCP-порт |
| Web UI (платно) | Опционально позже — встроенный веб-интерфейс только для чтения |
| MOS / jitter (VoIP) | Jitter, MOS-оценка — сразу |

Тёмная тема: чистый чёрный фон (#000/#0A0A0A), зелёный/жёлтый/красный фон зон на графиках как в PingPlotter, но приглушённые.

## 2. Технологический стек (универсальный под Mac и Windows)

**Tauri 2 + Rust (ядро) + React/TypeScript (интерфейс)**

Почему:
- Один код для macOS, Windows, Linux; нативные бинарники ~10–15 МБ (Electron ~150 МБ).
- Rust — быстрое и надёжное сетевое ядро: сотни целей × интервал 1–2.5 с без нагрузки на CPU.
- Веб-интерфейс даёт свободу в дизайне тёмной темы и сложных графиков.
- Нативные уведомления, трей/меню-бар, автозапуск, автообновление — есть плагины Tauri.

Альтернативы, которые рассмотрены и отклонены: Electron (тяжёлый), Flutter (слабее с низкоуровневой сетью), Qt/C++ (дольше разработка), SwiftUI (только Mac).

Компоненты:
- **Сетевое ядро** (Rust, tokio): свой движок ICMP/UDP/TCP-трассировки.
- **Хранилище**: SQLite (rusqlite) — сэмплы, агрегаты, события, конфиг.
- **Графики**: uPlot или собственный canvas/WebGL-рендер (миллионы точек, 60 fps).
- **UI**: React + TypeScript + Zustand (state) + TanStack Table (таблицы).

## 3. Ключевая техническая часть — пинг и трассировка без root/админа

| ОС | Способ |
|---|---|
| macOS | Непривилегированный ICMP-сокет `SOCK_DGRAM + IPPROTO_ICMP` + `IP_TTL` — работает без sudo |
| Windows | WinAPI `IcmpSendEcho2Ex` с опцией TTL — без прав администратора |
| Linux | `SOCK_DGRAM` ICMP (ping_group_range) или capability `CAP_NET_RAW` |

Всё прячется за Rust-трейтом `Prober` — остальной код не знает, на какой ОС работает.

Алгоритм трассировки (как у PingPlotter):
1. Discovery: пакеты с TTL = 1..30 → находим хопы до цели.
2. Далее каждый интервал (по умолчанию 2.5 с) параллельно шлём пакеты на **все хопы сразу** (TTL-пробы), а не последовательно.
3. Для каждого сэмпла пишем RTT или «потерян» по каждому хопу.
4. Периодически повторяем discovery → детектируем смену маршрута.

Типы проверок:
- ICMP-трассировка (основной режим), UDP, TCP-SYN (для хостов, блокирующих ICMP)
- Простой ping (без хопов) — для сотен целей дешевле
- HTTP(S): статус, время DNS/TCP/TLS/TTFB, срок SSL-сертификата
- TCP-порт (open/closed + время коннекта)
- DNS: время резолва, ожидаемый ответ

Метрики: min / avg / max / cur / jitter / packet loss % / MOS, по хопам и по конечной цели.

## 4. Архитектура

```
┌──────────────────────── UI (React/TS, WebView) ────────────────────────┐
│ Дашборд │ Детали цели (Trace + Timeline) │ Сводка │ Алерты │ Настройки │
└───────────────▲──────────────── IPC (Tauri commands/events) ───────────┘
                │ подписка на стрим сэмплов, запросы истории
┌───────────────┴──────────────── Rust core ─────────────────────────────┐
│ Scheduler ── Probers (ICMP/UDP/TCP/HTTP/DNS, платформенные бэкенды)    │
│     │                                                                  │
│ Aggregator (статистика, jitter, MOS, Focus) ── Route-change detector  │
│     │                                                                  │
│ Alert engine (правила → уведомления, Telegram, Slack, webhook, e-mail) │
│     │                                                                  │
│ Storage (SQLite: raw + rollup 1m/1h, ретеншн) ── Export (CSV/JSON)     │
│ DNS/ASN/Geo resolver (кэш)                                             │
└────────────────────────────────────────────────────────────────────────┘
```

Принцип: ядро — отдельный Rust-крейт `netpulse-core` без зависимости от UI.
Это позволяет позже сделать headless-агент/сервис (круглосуточный мониторинг на сервере) и веб-интерфейс на том же ядре.

Хранение данных:
- raw-сэмплы — N дней (настраивается, по умолчанию 7)
- агрегаты по 1 мин — 90 дней, по 1 часу — 2 года
- так история не раздувает диск даже при 200 целях

## 5. Интерфейс (тёмная тема, чёрный фон)

**Главный экран — Дашборд**
- Слева: дерево групп/тегов, поиск, кнопка «+ цель», импорт списка.
- Центр: таблица/плитки целей: статус-точка, имя, хост, текущий пинг, потери %, jitter, спарклайн за 15 мин/1 ч, аптайм за 24 ч.
- Сортировка «сначала проблемные», фильтры по статусу.

**Экран цели (клик по цели)** — развитие того, что на скриншоте:
- Верх: таблица хопов (Hop, IP, DNS-имя, ASN, Avg/Min/Cur/Max, Jitter, PL%, latency-бар с min-max и точкой текущего). Хоп, где начинаются потери, подсвечивается.
- Низ: Timeline-графики — конечная цель + любой выбранный хоп (клик по строке). Цветные зоны фона, красные столбики потерь, маркеры смены маршрута и алертов.
- Выбор окна: 5 мин / 1 ч / 6 ч / 24 ч / 7 дн / произвольно, зум колесом, выделение диапазона = Focus.
- Вкладки: Трассировка │ HTTP/порт │ События │ Настройки цели.

**Сводка**: аптайм и SLA по группам, топ проблемных, heatmap по часам/дням, журнал инцидентов.

**Меню-бар/трей**: иконка-индикатор (зелёная/жёлтая/красная), список упавших сервисов, приложение продолжает мониторить свёрнутым.

## 6. Этапы разработки

### Этап 0 — Каркас (1–2 дня)
- Репозиторий, Tauri 2 + React + TS, Rust workspace (`core`, `app`).
- Тёмная тема, дизайн-токены, базовый layout.
- CI (GitHub Actions): сборка macOS (universal: Intel+Apple Silicon) и Windows.

### Этап 1 — Сетевое ядро (MVP-ядро)
- ICMP ping без root на macOS, трейт `Prober`.
- Трассировка: discovery хопов + параллельные пробы по TTL.
- Scheduler на много целей, статистика, reverse DNS.
- CLI для отладки: `netpulse-cli trace 8.8.8.8`.

### Этап 2 — MVP интерфейса
- Дашборд с множеством целей, добавление/удаление/группы.
- Экран цели: таблица хопов + Timeline в реальном времени.
- Сохранение конфигурации.

### Этап 3 — История и анализ
- SQLite, rollup-агрегаты, ретеншн.
- Просмотр истории, зум, Focus-диапазон, сводные графики.
- Экспорт CSV/JSON, PNG-снимок графика.

### Этап 4 — Алерты
- Правила: потери > X% за N мин, пинг > Y мс, недоступно, смена маршрута, HTTP ≠ 200, SSL истекает.
- Каналы: системные уведомления, звук, Telegram, Slack/webhook, e-mail (SMTP).
- Журнал событий, «тишина» и гистерезис (без спама).

### Этап 5 — Расширенные проверки
- TCP/UDP-трассировка, HTTP(S), TCP-порт, DNS.
- ASN/провайдер и гео для хопов (офлайн-база).
- Jitter/MOS, детектор смены маршрута с diff.

### Этап 6 — Windows
- Бэкенд `IcmpSendEcho2Ex`, тесты, установщик MSI/NSIS, трей.
- Благодаря архитектуре — в основном только платформенный слой.

### Этап 7 — Полировка и дистрибуция
- Меню-бар, автозапуск, автообновление.
- Подпись/нотаризация для macOS (нужен Apple Developer аккаунт, иначе запуск через «Открыть» в Gatekeeper).
- Импорт/экспорт конфигурации для коллег.

### Позже (опционально)
- Headless-агент на Linux-сервере + веб-интерфейс только для чтения.
- Несколько агентов из разных офисов в одном дашборде.
- Метрики в Prometheus/Grafana.

## 8. Риски и как их закрываем

| Риск | Решение |
|---|---|
| Промежуточные хопы режут ICMP → «ложные» потери | Как в PingPlotter: потери на хопе важны, только если продолжаются до цели — UI это явно показывает |
| Сотни целей → нагрузка/флуд | Лимит параллельных проб, джиттер старта, режим «простой ping» для массовых целей |
| macOS App Sandbox запрещает сырые сокеты | Распространяем вне App Store (DMG), DGRAM-ICMP работает |
| Рост базы | Rollup + ретеншн |
| Графики тормозят на длинной истории | Downsampling (LTTB) на стороне Rust + canvas-рендер |

## 10. Принятые решения (ответы)

- Целей: до 50 → хватает одного процесса без отдельного агента, по умолчанию интервал 2.5 с.
- HTTP(S)-проверки: **да** (код ответа, время, ключевое слово, срок SSL).
- Каналы оповещений настраиваются в самой программе: системные, звук, Telegram, вебхук (Slack/Discord/JSON), e-mail SMTP, кнопки «Тест».
- Платформы: полноценное приложение на Mac (моё и руководителя) и `.exe` для IT на Windows. Обмен списком целей — экспорт/импорт JSON.
- Название: **NetPulse**.
